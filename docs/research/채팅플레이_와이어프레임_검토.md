# 채팅 플레이 와이어프레임 수정사항

작성일: 2026-11-17

검토 대상: 공유된 데스크톱 화재 시나리오 플레이 화면 이미지

목적: 화면 구현 전 정보 배치·사용자 흐름·예외 상태를 정리한다.

## 전체 평가

왼쪽에 현재 장면, 오른쪽에 대화를 배치해 상황 파악과 행동 입력의 흐름이 명확하다. 이 구성을 유지하면서 **현재 임무, 이전 선택의 영향, 남은 판단 기회**를 추가한다. 색상과 장식보다 이 세 가지를 먼저 반영한다.

## 1. 우선 반영할 수정사항

| 우선순위 | 수정사항 | 권장 위치·표현 | 완료 기준 |
|---|---|---|---|
| 필수 | 현재 임무 표시 | 제목 아래에 “동료와 함께 건물 밖으로 대피하고 상황 전달하기” | 대화가 길어져도 전체 목표를 확인할 수 있다. 단계별 정답은 미리 표시하지 않는다. |
| 필수 | 이전 선택의 영향 표시 | 진행 영역 아래에 “주변 알림 완료” 또는 “다른 직원의 도움으로 경보 작동” | 서버가 확정한 이력이 표시되고, 플레이하지 않은 행동을 완료로 표시하지 않는다. |
| 필수 | 남은 판단 기회 표시 | 입력창 위 또는 단계 표시 옆에 “이번 단계 판단 기회 2회” | 단계당 3회 제한을 알 수 있다. 차단 입력·API 장애에서 줄지 않고 새 단계 진입 시 초기화된다. |
| 필수 | 응답 대기·오류 상태 추가 | 입력창과 채팅 영역 | 중복 제출을 막고, 실패 시 작성한 문장을 복원한다. 처리 여부가 불명확한 요청은 중복 처리 방지 정책과 함께 설계한다. |
| 필수 | 종료 상태 추가 | 입력창 영역을 결과 안내와 “판단 복기 보기” 버튼으로 전환 | 건물 밖 도착 여부와 행동 기준 충족도를 구분한다. 도착만으로 모든 판단이 옳았다고 표현하지 않는다. |
| 필수 | 모바일 배치 추가 | 별도 모바일 와이어프레임 1장 | 키보드가 올라와도 입력창·보내기 버튼이 보이고 가로 스크롤이 없다. |
| 권장 | 단계 전환 구분 | 채팅 안에 “2단계 · 엘리베이터 앞” 구분선 | 어느 장면의 대화인지 구별된다. 이전 단계 접기를 넣더라도 다시 펼쳐 볼 수 있다. |
| 권장 | 위험도 변화 원인 표시 | 위험도 게이지 근처에 “위험도 +3 · 위험 행동” | 숫자·문구를 함께 사용한다. 서버가 확정하지 않은 원인을 화면이 추측하지 않는다. |

## 2. 장면과 대화의 역할 구분

- **왼쪽 장면 패널:** 현재 장면 이미지, 단계 제목, 현재 상황 설명을 유지한다. 대화가 길어져도 현재 상황을 다시 확인하는 공간이다.
- **오른쪽 대화 패널:** 사용자·캐릭터 대화와 장면 전환 이력을 표시한다. 현재 상황 설명 전체를 매번 반복하지 않는다.
- **단계 변경 시:** 왼쪽 패널을 새 상황으로 갱신하고 오른쪽에 단계 구분을 추가한다. 이전 사용자 발언을 현재 단계 발언처럼 보이게 하지 않는다.
- **이전 선택의 영향:** 단순한 장식 배지가 아니라 다음 상황과 연결되는 사실만 보여준다. 예: 직접 알림을 완료한 경로와 다른 직원이 대신 경보를 울린 경로를 구별한다.

## 3. 권장 데스크톱 배치

```text
시나리오 제목 / 목록 이동
전체 임무
────────────────────────────────────────
현재 단계·단계 제목             위험도
이전 선택의 영향
────────────────────────────────────────
현재 장면                     대화 이력
이미지                        단계 구분
상황 설명                     캐릭터·사용자 발언
                              응답 대기 / 오류 안내
                              남은 판단 기회
                              행동 입력창 / 보내기
```

상단 상태 영역과 입력창은 유지하고 대화 영역을 중심으로 스크롤한다. 작은 화면 높이에서도 장면 패널 때문에 입력창이 밀려나지 않게 확인한다.

## 4. 반드시 그릴 화면 상태

| 상태 | 화면 처리 | 주의사항 |
|---|---|---|
| 최초 준비 중 | 상황 로딩 안내, 입력 비활성화 | 빈 화면으로 멈춘 것처럼 보이지 않게 한다. |
| 정상 입력 | 행동 입력, 글자 수, 보내기 버튼 | 입력창에 접근성 이름을 제공한다. 공백만 입력하면 보내기를 막는다. |
| 응답 대기 | 사용자 임시 말풍선, “상대가 반응하는 중”, 중복 전송 방지 | 실제 AI 응답 시간과 무관한 가짜 진행률은 표시하지 않는다. |
| 입력 차단 | 대화 내 안내, 다시 입력 가능 | 위험도·판단 기회를 임의로 줄이지 않는다. |
| 추가 행동 확인 필요 | 캐릭터가 구체적인 행동을 되묻기 | 미확인을 무조건 위험 행동이나 오답으로 표시하지 않는다. |
| 통신·AI 오류 | 오류 안내, 작성 문장 복원 또는 재입력 안내 | 장애를 사용자의 판단 실패로 표현하지 않는다. 재전송 시 중복 처리 가능성은 백엔드와 함께 해결한다. |
| 단계 전환 | 새 장면·제목 갱신, 채팅 구분 추가 | 이전 선택 상태와 새 설명이 모순되지 않아야 한다. |
| 건물 밖 도착 | 도착 안내, 입력 종료, 판단 복기 버튼 | “모든 판단 정답”과 구분한다. |
| 위험도 한도 도달 | 대피 중단 안내, 입력 종료, 판단 복기 버튼 | 실패를 과도하게 자극적으로 묘사하지 않는다. |
| 목록 이동 | 기록 유실 가능성이 있으면 안내 | 현재는 메모리 저장이며 이어하기가 미구현이다. 저장됐다고 안내하지 않는다. |

## 5. 모바일 와이어프레임

```text
시나리오 제목 / 목록
현재 단계 / 위험도 / 남은 기회
전체 임무·선택 이력 요약
현재 장면 [펼치기 / 접기]
──────────────────
스크롤 가능한 대화 영역
──────────────────
행동 입력창 / 보내기
```

- 장면을 접어도 현재 단계 제목은 남긴다.
- 터치 버튼은 충분한 크기와 간격을 확보한다.
- 오류 안내가 입력창이나 키보드 뒤에 숨지 않도록 한다.
- 색만으로 상태를 구분하지 않고 숫자·문구·아이콘을 함께 사용한다.

## 6. 현재 API로 표시 가능한 정보

| 화면 요소 | 현재 데이터 | 구현 상태·제약 |
|---|---|---|
| 전체 임무 | `ScenarioSummary.briefing.mission` | 서버 제공 |
| 현재 단계 | `Turn.stage`, `stage_title`, `total_stages` | 서버 제공 |
| 위험도 | `Turn.risk`, `max_risk` | 서버 제공 |
| 이전 선택 영향 | `Turn.conditions` | 서버가 확정한 상태 문구 제공 |
| 남은 판단 기회 | `Turn.attempts_left` | 서버 제공, 종료 시 0 |
| 새 대화 | `Turn.messages` | 이번 턴에 추가된 메시지만 제공 |
| 종료 여부 | `Turn.status` | playing / cleared / failed |
| 장면 이미지 | `Turn.image` | 경로 데이터는 있으나 실제 파일 제공·로딩 실패 처리는 별도 확인 필요 |
| 왼쪽 현재 상황 설명 | `Turn.messages`의 narrator | 메시지에 상황·선택 결과가 함께 포함될 수 있어 자동 추출만으로는 불명확하다. 전용 `situation` 필드를 추가하는 편이 안정적이며 아직 미구현이다. |
| 실시간 위험도 변화 원인 | 이전·현재 risk와 메시지 | 증가량은 계산 가능하지만 정확한 사유 전용 필드는 없다. 사유 표시에는 API 보완 필요. |
| 종료 판단 타임라인 | `Report.timeline` | 리포트에서 제공하며 현재 플레이 응답에는 포함되지 않음 |

API와 구현 상태의 기준은 [API 명세](../api-spec.md)와 [판단 복기 설계](../decision-design.md)를 따른다. 위 표의 미구현 항목을 이미 동작하는 기능처럼 와이어프레임 설명에 적지 않는다.

## 7. 화면 검수 체크리스트

- [ ] 현재 역할·전체 목표·단계가 구분되는가?
- [ ] 직접 수행한 행동과 도움받은 행동이 다르게 표시되는가?
- [ ] “음...”을 3회 입력한 경로가 성공 경로와 다른 설명으로 이어지는가?
- [ ] 입력 차단·API 오류에서 위험도와 판단 기회가 유지되는가?
- [ ] 전송 중 연속 클릭이나 Enter 입력으로 중복 제출되지 않는가?
- [ ] 오류 뒤 작성한 문장을 잃지 않고 다시 시도할 수 있는가?
- [ ] 종료 후 입력이 막히고 판단 복기로 이동할 수 있는가?
- [ ] 대피 장소 도착과 행동 기준 충족도를 혼동하지 않는가?
- [ ] 작은 노트북 화면과 모바일 키보드 환경에서 입력창이 보이는가?
- [ ] 장면 이미지가 없어도 제목·상황 설명으로 플레이할 수 있는가?
- [ ] 목록 이동·새로고침 때 실제 저장·이어하기 지원 범위와 안내가 일치하는가?

이 문서는 와이어프레임 검토 결과이며, 문서 작성만으로 화면 수정이나 브라우저 검증이 완료된 것은 아니다.
