# API 키 없이 품질 높이기

작성: 2026-11-17. 아래 역할은 팀 합의 전 제안이며 기존 담당 업무를 대체하지 않는다.

## 이번에 구현한 것

- 시작 전 브리핑: 상황, 임무, 등장인물, 플레이 방법을 확인하고 세션 시작.
- 플레이 중 목표 표시와 입력창·대화 영역 접근성 이름 추가.
- 리포트에 단계별 실제 발언과 판단 시도 횟수 표시. 안전 필터 차단 발언은 제외.
- 고정 리포트 문구를 규칙 기반 판정에 맞게 수정.
- 리포트 API 회귀 테스트 추가.
- 후속 개선 완료: 단계별 다중 행동 근거 누적, 위험 행동 우선 판정, 도움 여부에 따른 다음 장면 변형, 판단 타임라인·항목별 출처·다음 연습 포인트 추가. 상세는 [현재 설계](decision-design.md) 참조.
- 원격 PR #8에서 화재 출처 링크·키워드 검수가 반영됨. 아래 출처 작업은 완료 전제가 아니라 새 rubric과 출처의 대응을 재검수하는 작업으로 읽는다.

## 다음 작업과 완료 기준

| 순서 | 작업 | 결과물과 완료 기준 | 담당 제안 |
|---|---|---|---|
| 1 | 화면 직접 체험 | 브리핑 → 성공 플레이 → 리포트, 위험 플레이 → 실패 리포트를 각각 진행. PC·모바일 폭에서 입력창과 버튼이 보이는지 확인하고 문제 화면 기록 | 곽동규 |
| 2 | 행동 기준 출처 재검수 | 반영된 상세 출처와 새 rubric 항목을 대조해 과소·과대 평가, 표현 누락과 수정 제안 기록 | 조민선 |
| 3 | 판정 사례 수집 | 단계마다 정답 표현 3개, 위험 표현 3개, 애매한 질문 2개를 표로 작성. 실제 판정과 기대 판정을 비교해 잘못된 사례 기록 | 김채희 |
| 4 | 시나리오 연결 검수 | 구현된 성공·도움 경로를 비교하고 다음 장면의 상황·첫 대사가 선택 이력과 맞는지 검수 | 팀 공동 |
| 5 | 상태 저장·이어하기 | 서버 재시작 후에도 동일 세션을 이어가고 종료 리포트 조회. 세션 만료·소유권·중복 요청 처리까지 설계하고 검증 | 장우석 |
| 6 | 상황 변형 확장 | 현재 다섯 단계의 상태 기반 장면 변형을 실제 사용자에게 검증하고, 필요하면 다른 경로로 이동하는 분기 트리 설계 | 장우석 + 콘텐츠 담당 |
| 7 | 장면 시각화 | 검수한 장면 5개에 맞춰 이미지·대체 설명을 준비하고 실제 파일 제공·로딩 실패 처리 연결. 현재 image는 경로 데이터만 있음 | 곽동규 + 팀 |

## 초보 팀원에게 작업을 전달하는 방법

한 번에 표의 한 행만 맡긴다. 담당자는 수정 전 기존 파일을 읽고, AI에게 변경 목적과 확인 방법을 설명받는다. 결과물은 새 문서 또는 작은 변경으로 만들고, 무엇을 바꿨고 무엇을 실제 확인했는지 자신의 말로 기록한다. PR 검토·머지는 장우석이 진행한다.
