| 곽동규 | 유사 서비스 조사 + 화면 설계 → 프론트 | [곽동규.md](곽동규.md) |
| 김채희 | AI 프롬프트 · 안전(인젝션·선정성) 테스트 | [김채희.md](김채희.md) |
| 조민선 | 시나리오 콘텐츠 · 안전교육 조사 · 검증 | [조민선.md](조민선.md) |

## 먼저 할 것 (전원, 30분)

0. **[협업 가이드](../협업가이드.md) 읽기** — GitHub Desktop으로 작업 올리는 방법
1. 레포를 받고(GitHub Desktop → Fetch/Pull) 루트 `README.md` 의 "처음 받았을 때"대로 설치
2. `python play_test.py` 실행 → 화재 시나리오가 3번 자동으로 도는 걸 눈으로 확인
3. `uvicorn app.main:app --reload` → http://localhost:8000/docs 에서 **직접 한 판 플레이**
   (`POST /sessions` 에 `{"scenario_id": "fire_office"}` → 받은 `session_id` 로 `POST /sessions/{id}/messages`)
4. `data/scenarios/fire_office.json` 을 열어 "시나리오 = 단계 문서"가 어떻게 생겼는지 보기

막히면 단톡에 화면 캡처와 함께 바로 질문. 혼자 1시간 넘게 붙잡지 않는다.

## 작업 방식

1. `main` 에 직접 push 하지 않는다. 브랜치에서 작업 → PR → **장우석이 확인 후 머지.** (GitHub Desktop 사용, 충돌은 장우석에게)
2. 매일 단톡에 한 줄: **어제 한 것 / 오늘 할 것 / 막힌 것**
3. 각자 파일의 체크박스는 끝날 때마다 체크해서 PR에 같이 올린다.
4. **AI 도구 사용 규칙**
   - 일은 작게 쪼개서 시킨다 ("화면 전체 만들어줘" ✕ → "시나리오 카드 컴포넌트 하나 만들어줘" ○)
   - 받은 코드·글은 "초보자에게 설명해줘"로 이해하고 넘어간다. **멘토가 물어보면 내가 설명할 수 있어야 한다.**
   - API 키·개인정보는 절대 채팅창에 붙여넣지 않는다.
   - AI가 만든 사실(통계, 출처, 행동요령)은 반드시 원문으로 확인한다. AI는 그럴듯한 가짜 출처를 만든다.
