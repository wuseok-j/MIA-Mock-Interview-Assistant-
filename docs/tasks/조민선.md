# 조민선 — 자료 · 검증 · 사용량/비용 · 발표

**담당 파일:** `data/question_bank.json`, `data/` 아래 검증 자료, 비용 계산표, 발표 PPT

## 2주차 (~11/15) — 질문은행이 가장 급함
- [ ] 질문은행 5개 → **20개** (1주차 목표였음. 김채희가 프롬프트 테스트에 바로 씀)
  - 형식은 기존 항목 그대로: `id`, `category`, `question`, `rubric`(항목 3개)
  - 분야: 데이터베이스 · 네트워크 · API 설계 · 협업 경험
  - 외부 자료 문장을 그대로 복사하지 않고 다시 쓰기
- [ ] 검증용 입력 20건 작성: 좋은 답변 · 모호한 답변 · 동문서답 · 인젝션 시도 **각 5건**, 건마다 기대 결과 함께 적기
  - 자기소개서는 **가상 인물**로 (실제 개인정보를 API에 보내지 않음)

## 3주차 (11/16 ~ 11/22)
- [ ] 질문은행 **40개** 완성, 팀원 1명과 교차 검토
- [ ] 검증 20건 실행 → 기대 결과와 비교한 **검증 결과표** (목표: 20건 중 16건 이상 일치)
- [ ] 인젝션 자기소개서 5건으로 점수 조작 시도 → 결과를 김채희에게 전달
- [ ] **사용량 제한:** 사용자당 하루 면접 3회 (장우석과 붙일 위치 상의)
- [ ] **토큰 기록:** 면접마다 입력 · 출력 토큰 수를 남기기 (김채희와 기록 방식 상의)

## 4주차 (11/23 ~ 11/27)
- [ ] 실제 기록으로 **면접 1회당 비용 계산표** (진행 · 평가 모델 각각, 원화 환산)
- [ ] 시연 시나리오: 예시 자기소개서로 면접 1회 → 리포트, 인젝션 자기소개서로 점수 조작이 막히는 장면
- [ ] 발표 PPT: 구현 화면, 시스템 구성도, 하네스 설계, 검증 결과표, 비용 계산, 한계 · 개선 방향, 역할별 기여
- [ ] (시간 되면) 취업 준비생 설문

## 협업
- **김채희:** 질문은행 · 루브릭 형식, 검증 결과와 실패 사례
- **장우석:** 사용량 제한 · 토큰 기록을 서버에 연결
- **전원:** 발표 자료 받기 (화면 캡처 · 프롬프트 개선 내역 · 구성도)
