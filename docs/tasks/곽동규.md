# 곽동규 — 유사 서비스 조사 · 화면 설계 → 프론트엔드

**결과물 위치:** `docs/research/유사서비스_조사.md`, `docs/research/화면목록.md`, (4주차) `frontend/`

## 왜 이 일이 중요한가
멘토가 "크랙·제타·뮤즈 같은 캐릭터 채팅 서비스를 조사하라"고 직접 말했다. 우리 서비스가 **왜 롤플레잉이어야 하는지**, 그 시장에서 **무엇을 배워 오고 무엇이 다른지**를 설명하는 근거가 이 조사다.
그리고 멘토 말대로 "화면이 정해지면 DB 구조가 따라 나온다." 화면 목록은 장우석이 DB를 짜는 출발점이다.

## 3주차 (11/16 ~ 22) — 멘토 미팅 전까지

### 1. 유사 서비스 조사 (가장 먼저)
- [ ] 크랙 · 제타 · 뮤즈를 **직접 설치해 각각 20분 이상** 써 보기 (성인 콘텐츠는 보지 않는다)
- [ ] 서비스마다 아래 표 채우기 → `docs/research/유사서비스_조사.md`

  | 항목 | 크랙 | 제타 | 뮤즈 |
  |---|---|---|---|
  | 주 사용자 (나이·성별 추정) | | | |
  | 인기 이유 (직접 써 보고 느낀 점) | | | |
  | 수익 모델 (구독·재화·광고, 가격) | | | |
  | 캐릭터를 누가 만드나 (운영사/이용자) | | | |
  | 대화가 '단계'처럼 진행되는 느낌이 있나 | | | |
  | 화면 구성 (목록·채팅·프로필) 캡처 | | | |

- [ ] 표 아래에 **"우리가 가져올 것 3가지 / 우리가 다른 점 3가지"** 정리
  - 예: 가져올 것 = 캐릭터 프로필·첫 대사로 몰입시키는 방식 / 다른 점 = 정해진 단계와 평가 리포트가 있음, 교육 목적, 10대 안전
- [ ] 비슷한 "교육용 롤플레잉"이 이미 있는지 검색 (예: 안전교육 VR, 시뮬레이션 교육) → 있으면 이름·가격·한계 2~3줄씩

> AI 활용 팁: 조사 결과를 붙여 넣고 "이 내용을 표로 정리하고, 빠진 항목을 질문해줘"라고 시키면 좋다.
> 단, 앱 기능·가격은 **직접 확인한 것만** 적는다. 확인 못 했으면 "미확인"이라고 쓴다.

### 2. 화면 목록 (조사 끝나고)
- [ ] `docs/research/화면목록.md` 에 화면 이름 + 그 화면에 보이는 요소를 적기
  - **이용자:** 로그인 / 시나리오 목록 / 시나리오 상세 / 채팅 플레이 / 리포트 / 플레이 기록
  - **운영자(CMS):** 시나리오 목록 / 시나리오 편집(기본정보·캐릭터·단계) / 이용 통계
- [ ] 채팅 플레이 화면은 손그림이나 피그마로 **와이어프레임 1장** (장면 이미지, 위험도 게이지, 단계 표시, 말풍선, 입력창)
  - 참고: `docs/api-spec.md` 의 Turn 응답에 화면에 필요한 값이 다 들어 있다
