# 시나리오 작성 가이드

이 폴더의 `*.json` 파일 하나가 시나리오 하나다. 서버는 시작할 때 이 폴더를 읽어서 자동으로 목록에 올린다.
**새 시나리오는 `fire_office.json` 을 복사해서 내용만 바꾸는 게 가장 쉽다.**

시나리오는 하네스의 "재료"다. AI는 이 문서를 보고 캐릭터 연기와 판정을 하고, 서버는 이 문서의 규칙으로 단계를 진행한다.
→ 문서가 구체적일수록 AI가 덜 헤매고, 정답 기준이 정확할수록 교육 효과가 생긴다.

## 전체 구조

| 필드 | 뜻 | 예시 |
|---|---|---|
| `id` | 영어 소문자·밑줄, 파일 이름과 같게 | `earthquake_school` |
| `title`, `summary`, `category` | 목록 카드에 보이는 정보 | "학교 지진 대응", "지진" |
| `role_doc` | **롤 문서**: 장소, 상황, 캐릭터가 지킬 규칙 | |
| `characters` | 등장인물 (이름, 역할, 성격, 말투) — 실존 인물 이름 금지 | |
| `max_risk` | 위험도가 이 값 이상이 되면 실패로 끝남 | 6 |
| `stages` | **단계 문서** (아래) | 4~6개 권장 |
| `evaluation` | 리포트 체크 항목. 보통 단계마다 1개 | |
| `sources` | 정답 근거로 쓴 공공기관 자료 | |

## 단계(stage) 한 개

| 필드 | 뜻 | 작성 요령 |
|---|---|---|
| `stage` | 단계 번호 1, 2, 3 … | |
| `title` | 화면에 보이는 단계 이름 | 짧게 |
| `situation` | 이 단계 상황 설명 (내레이션) | 2문장 이내, 눈에 보이는 것 위주 |
| `character_id` | 이 단계에서 말하는 캐릭터 | `characters` 의 id |
| `opening_line` | 캐릭터 첫 대사 | **일부러 틀린 행동을 유도**하면 판단 연습이 된다 (예: "엘리베이터 타자!") |
| `correct_action` | 올바른 행동 | 공공기관 행동요령 근거. 리포트에 정답으로 그대로 보인다 |
| `keywords` | 올바른 행동으로 인정할 표현 | **넉넉히** (동의어, 띄어쓰기 변형). 서버가 이 중 하나는 있어야 통과시킨다 |
| `wrong_keywords` | 위험한 행동 표현 | 가짜 AI 판정에 쓰임 |
| `next_if_correct` | 맞히면 갈 단계 번호 | 마지막 단계는 `null` |
| `if_wrong.narration` | 틀렸을 때 상황 변화 | 끔찍한 묘사 금지 ("기침을 한다" 수준) |
| `if_wrong.risk_delta` | 틀렸을 때 올라가는 위험도 | 1~3 |
| `reactions` | 캐릭터 반응 대사 (correct / wrong / unclear) | AI 오류 시 대신 쓰는 예비 대사이기도 함 |
| `image` | 장면 이미지 파일 이름 | 이미지는 아직 없어도 됨 |

## 진행 규칙 (서버가 강제)

- 한 단계에서 판단 기회는 **3번**. 맞히면 다음 단계, 3번 안에 못 맞히면 '실패'로 기록하고 다음 단계로 넘어간다.
- 틀린 행동마다 `risk_delta` 만큼 위험도가 오르고, `max_risk` 이상이면 그 자리에서 실패로 끝난다.
- "정답 알려줘", "다음 단계로 넘겨" 같은 말은 서버 필터가 막는다 (단계·위험도 변화 없음).

## 작성 후 확인

```bash
cd backend
python play_test.py          # fire_office 기준 자동 플레이
uvicorn app.main:app --reload   # http://localhost:8000/docs 에서 새 시나리오로 직접 플레이
```
JSON 문법 오류가 있으면 서버가 켜지지 않는다. VS Code에서 열면 빨간 줄로 위치를 알려 준다.
